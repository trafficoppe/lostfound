## 3. เงื่อนไขหยุดและย้อนกลับ

หยุดและย้อนกลับ (ตาม README หัวข้อ "การย้อนกลับ") เมื่อ:
- health ไม่ตอบ / ตอบ error หลัง Deploy เกิน 5 นาที
- ส่งฟอร์มจริงแล้ว `LF_New` ไม่มีแถวใหม่ หรือหน้าแบบฟอร์มแจ้ง error
- `LF_NotifyLog` มีการส่งซ้ำของ RefCode เดียวกันในช่องทางเดียวกัน
- API สาธารณะมีคีย์ `name`/`phone`/`dept`/`personType`/`updatedBy`
- หน้า index/Dashboard โหลดไม่ได้หลัง Pages อัปเดต (ย้อนเฉพาะหน้าเว็บด้วย `git revert` ก่อน)

วิธีย้อน Apps Script: วางโค้ด 2 ไฟล์ที่สำรองในขั้น 0 กลับเป็น Head โดย **คง `config.private.gs` ปัจจุบัน** แล้ว Deploy deployment เดิมเป็น New version
— รหัส `admin01` ใหม่ (ขั้น 2ข) ยังมีผล เพราะ web app ใช้ config ของรุ่นที่ deploy
ห้ามใช้การเลือก deployment version เก่าโดยตรง เว้นแต่ฉุกเฉิน: รุ่นเก่าเก็บ config เก่าไว้ รหัสเดิมที่เคยอยู่ในประวัติสาธารณะจะกลับมาใช้ได้ทันที → ต้องทำวิธีข้างต้นต่อทันที

การย้อนกลับ **ไม่คืนชีทหรือ Script properties จากสำรอง** — รายการใหม่อยู่ใน `LF_New` เสมอ, คิวและสถานะรายงานรุ่นเดิมอ่านได้โดยไม่ส่งซ้ำ
(ทดสอบกับโค้ดจริง 2.0.0 แล้ว: รายการไม่แน่ใจ/ปิดแล้ว/กำลังส่ง ไม่ถูกรุ่นเดิมส่งซ้ำ; รายงานรายเดือนที่มีช่องทางส่งแล้วไม่ถูกส่งซ้ำ)

## 5. ทดสอบแจ้งเตือนกับปลายทางจริงแบบควบคุมผลกระทบ

ไม่ส่งฟอร์มปลอมเข้าระบบจริง (จะเข้ารายการสาธารณะและรายงานรายเดือน)

- **แบบไม่ส่งอะไรเพิ่ม (แนะนำ)**: รอรายการจริงรายการถัดไป แล้วตรวจที่หน้า "ตรวจการแจ้งเตือน"/`LF_NotifyLog` ว่า LINE และอีเมล = `sent` ครั้งเดียว
- **แบบส่งข้อความทดสอบ 1 ครั้ง** (ต้องอนุมัติเวลาและผู้รับ): ผู้ดูแลรัน `testNewFormNotification` จากตัวแก้ไข Apps Script 1 ครั้ง
  - ผู้รับ: กลุ่ม LINE ตาม `lineWebhookUrl` + อีเมลตาม `emailRecipients` ใน `config.private.gs` (ไม่เปลี่ยนผู้รับ)
  - ข้อความ: ประเภท "พบสิ่งของ", ผู้แจ้ง "ทดสอบระบบ (ไม่ใช่ผู้แจ้งจริง)", รายละเอียด "[ทดสอบระบบหลังปรับปรุง v2.1.1] ไม่ต้องดำเนินการ"
  - ไม่เพิ่มแถวในชีท ไม่เข้ารายงานรายเดือน; ผลอยู่ใน `LF_NotifyLog` RefCode ขึ้นต้น `TEST-`
- รายงานรายเดือน: ไม่ทดสอบส่งจริงก่อน 1 พ.ย. — ตรวจผลรอบจริงวันที่ 1 พ.ย. หลัง 09:00 ที่หน้า "ตรวจการแจ้งเตือน" (แยก LINE/อีเมล)

## 8. ข้อจำกัดที่ยังเหลือ

- ระบบรับประกันไม่ได้ว่าข้อความถูกส่ง "ครั้งเดียวเสมอ": กรณีไม่แน่ใจต้องให้คนตรวจ (ดูกลุ่ม LINE แล้วเลือก "ยืนยันว่าได้รับ" หรือ "ส่งใหม่"); กติกาแยก "ยังไม่ส่ง" กับ "ไม่แน่ใจ" อิงโค้ด Cloud Function ในเครื่องผู้ดูแล (21 ต.ค.) ยังไม่ได้เทียบกับรุ่นที่ deploy อยู่ — ถ้า Cloud Function ถูกแก้ ต้องตรวจกติกาใหม่
- ถ้าย้อนกลับเป็น 2.0.0 ระหว่างวันที่ 1–3 และรายงานส่งไม่ครบ ช่องทางที่ค้างต้องส่งเอง
- การปิดบังชื่ออัตโนมัติจับชื่อบุคคลที่สามที่ไม่มีคำนำหน้าไม่ได้ (ดู README "ขอบเขตการปิดบังข้อมูล")
- เวลาเปิดหน้าครั้งแรกยังขึ้นกับ Apps Script (~2.5–7 วินาที) — การแก้ระดับโครงสร้าง (เช่น ไฟล์ข้อมูลสาธารณะแบบ static) อยู่ใน roadmap
- build ของรุ่น 2.0.0 ตรวจไม่ได้ (รุ่นนั้นไม่มีกลไกนี้) — ยืนยันรุ่นที่ใช้อยู่จาก health (`version`) และหมายเลข deployment
