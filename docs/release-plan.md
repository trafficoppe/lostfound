## 3. เงื่อนไขหยุดและย้อนกลับ

หยุดและย้อนกลับ (ตาม README หัวข้อ "การย้อนกลับ") เมื่อ:
- health ไม่ตอบ / ตอบ error หลัง Deploy เกิน 5 นาที
- ส่งฟอร์มจริงแล้ว `LF_New` ไม่มีแถวใหม่ หรือหน้าแบบฟอร์มแจ้ง error
- `LF_NotifyLog` มีการส่งซ้ำของ RefCode เดียวกันในช่องทางเดียวกัน
- หน้า "ตรวจการแจ้งเตือน" มีรายการ "ไม่ได้เข้าคิว" หรือพื้นที่คิวเกิน 80% โดยไม่ทราบสาเหตุ
- LINE เป็น "ไม่แน่ใจ" ทุกรายการ (เช่น URL ปลายทางผิด/ถูกย้าย) → ตั้ง `LF_QUEUE_PAUSE` = `1` ก่อน แล้วตรวจ URL ใน `config.private.gs`
- API สาธารณะมีคีย์ `name`/`phone`/`dept`/`personType`/`updatedBy`
- หน้า index/Dashboard โหลดไม่ได้หลัง Pages อัปเดต (ย้อนเฉพาะหน้าเว็บด้วย `git revert` ก่อน)

วิธีย้อน Apps Script (ตามลำดับ):
1. วางโค้ด 2 ไฟล์ที่สำรองในขั้น 0 กลับเป็น Head โดย **คง `config.private.gs` ปัจจุบัน** › Save — trigger กลับเป็นรุ่นเดิมทันที
2. Deploy deployment เดิมเป็น New version — รหัส `admin01` ที่ใช้อยู่ (หรือรหัสใหม่จากขั้น 2ข) ยังมีผล เพราะ web app ใช้ config ของรุ่นที่ deploy

ทำข้อ 1 ก่อนข้อ 2 เสมอ: web app รุ่นใหม่ใส่คิวแบบที่ตัวประมวลผลรุ่นเดิมส่งได้ครั้งเดียว (ทดสอบกับโค้ดจริง 2.0.0)

ฉุกเฉิน (เร็วกว่า): เลือก deployment version **ที่จดในขั้น 0 เท่านั้น** → web app กลับไปใช้ config ของรุ่นนั้น (รหัสที่ใช้ก่อนเผยแพร่ ซึ่งตั้งเมื่อ 19 ต.ค. ไม่เคยเผยแพร่)
แต่ trigger ยังเป็นโค้ดใหม่จนกว่าจะทำข้อ 1 (ทดสอบแล้วว่าไม่ส่งซ้ำ) · ถ้าปัญหาอยู่ที่การแจ้งเตือนของโค้ดใหม่ ให้ตั้ง Script Property `LF_QUEUE_PAUSE` = `1` ระหว่างรอทำข้อ 1 (ช่วงนั้นไม่มีอะไรถูกส่ง — ลบค่าหลังทำข้อ 1)
ห้ามเลือก version ที่เก่ากว่าขั้น 0: รุ่นก่อน 19 ต.ค. 2569 อาจมีรหัส 9 หลักเดิมที่เคยอยู่ในประวัติสาธารณะ

การย้อนกลับ **ไม่คืนชีทหรือ Script properties จากสำรอง** — รายการใหม่อยู่ใน `LF_New` เสมอ, คิวและสถานะรายงานรุ่นเดิมอ่านได้โดยไม่ส่งซ้ำ
(ทดสอบกับโค้ดจริง 2.0.0 แล้ว: รายการไม่แน่ใจ/ปิดแล้ว/กำลังส่ง ไม่ถูกรุ่นเดิมส่งซ้ำ; รายงานรายเดือนที่มีช่องทางส่งแล้วไม่ถูกส่งซ้ำ)

## 8. ข้อจำกัดที่ยังเหลือ

- ระบบรับประกันไม่ได้ว่าข้อความถูกส่ง "ครั้งเดียวเสมอ": กรณีไม่แน่ใจต้องให้คนตรวจ (ดูกลุ่ม LINE แล้วเลือก "ยืนยันว่าได้รับ" หรือ "ส่งใหม่")
  - นับว่าส่งแล้วเฉพาะ HTTP 2xx + `{"status":"success"}` ตามโค้ด Cloud Function ในเครื่อง (รุ่นที่ deploy อยู่เทียบไม่ได้ — Cloud Console ปฏิเสธบัญชี)
  - คำตอบ HTTP อื่นทุกแบบ (redirect, 4xx, 408, 429, 5xx) และหมดเวลา = ไม่แน่ใจ; ลองใหม่เองเฉพาะคำขอที่ยังไม่ออกจากระบบ
  - ผลต่อเจ้าหน้าที่: ถ้าปลายทางพังแบบตอบกลับ (เช่น 404 เพราะ URL ผิด) ทุกรายการจะเป็น "ไม่แน่ใจ" และต้องกดตัดสินทีละรายการ —
    อีเมลยังส่งปกติ, หน้า "ตรวจการแจ้งเตือน" แสดงจำนวน, ใช้ `LF_QUEUE_PAUSE` หยุดชั่วคราวได้ · ชุด e (4xx = ลองใหม่) ส่งซ้ำได้ถ้า 4xx เกิดหลังส่ง LINE แล้ว จึงเลือกให้คนตัดสิน
- ถ้าย้อนกลับเป็น 2.0.0 ระหว่างวันที่ 1–3 และรายงานส่งไม่ครบ ช่องทางที่ค้างต้องส่งเอง
- การปิดบังอัตโนมัติจับชื่อบุคคลที่สามที่ไม่มีคำนำหน้า, คำนำหน้า "คุณ"/"อ.", LINE ID ไม่ได้ (ดู README "ขอบเขตการปิดบังข้อมูล") — ด่านหลักคือไม่ส่งชื่อ/เบอร์/หน่วยงานออก API เลย
- เวลาเปิดหน้าครั้งแรกยังขึ้นกับ Apps Script (ข้อ 9) — การแก้ระดับโครงสร้าง (เช่น ไฟล์ข้อมูลสาธารณะแบบ static) อยู่ใน roadmap
- build ของรุ่น 2.0.0 ตรวจไม่ได้ (รุ่นนั้นไม่มีกลไกนี้) — ยืนยันรุ่นที่ใช้อยู่จาก health (`version`) และหมายเลข deployment
