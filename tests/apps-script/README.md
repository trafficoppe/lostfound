# ทดสอบบน Apps Script จริง ในโปรเจกต์แยกจากระบบจริง (ราว 20 นาที)

ทุกอย่างเกิดใน **ชีททดสอบ** ที่มีแต่ข้อมูลสังเคราะห์ (ชื่อขึ้นต้นด้วย `TEST`) — ลิงก์ชีทอยู่ในชุดส่งมอบ ไม่เก็บใน GitHub
ไม่มีขั้นใดแตะชีทจริง โปรเจกต์ Apps Script จริง กลุ่ม LINE หรือผู้รับอีเมลจริง
ฟังก์ชันทดสอบ **หยุดเองทันที** ถ้าตรวจพบว่าเชื่อมกับระบบจริง และไม่มีฟังก์ชันใดสร้าง/แก้/Archive deployment เอง

## ไฟล์ที่วางในโปรเจกต์ทดสอบ (4 ไฟล์ แทนทั้งไฟล์)

| ไฟล์ในโปรเจกต์ทดสอบ | วางเนื้อหาจาก |
| --- | --- |
| `Code.gs` (มีอยู่แล้ว ลบของเดิมทั้งหมด) | `apps-script/lf_gas.gs` |
| `MonthlyReport` | `apps-script/MonthlyReport.gs` |
| `config.test` | `tests/apps-script/config.test.gs` |
| `release_test` | `tests/apps-script/release_test.gs` |

**ห้าม** วาง `config.private.gs` หรือ `config.example.gs` ในโปรเจกต์ทดสอบ (ถ้ามี config สองไฟล์ สคริปต์จะไม่ทำงานเลย)

## ขั้นตอน

1. เปิดชีททดสอบ › **ส่วนขยาย › Apps Script** → เปิดโปรเจกต์ใหม่ที่ผูกกับชีททดสอบ
   - คลิกชื่อโปรเจกต์มุมซ้ายบน › ตั้งชื่อ `TEST Lost&Found (ลบได้)` — ใช้เป็นป้ายยืนยันว่าอยู่ในโปรเจกต์ทดสอบทุกครั้ง
2. วาง 4 ไฟล์ตามตารางด้านบน › 💾 บันทึก
3. **การทำให้ใช้งานได้ › การทำให้ใช้งานได้รายการใหม่** › ฟันเฟือง › **เว็บแอป**
   - ดำเนินการในฐานะ: **ฉัน** · ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน** › **ทำให้ใช้งานได้**
   - ครั้งแรกจะขอสิทธิ์ของ **โปรเจกต์ทดสอบนี้เท่านั้น**: เลือกบัญชี › ขั้นสูง › ไปที่โปรเจกต์ › **อนุญาต**
   - คัดลอก **URL เว็บแอป** (ลงท้าย `/exec`)
   - ถ้าไม่มีตัวเลือก "ทุกคน" (องค์กรปิดไว้) ให้หยุดและแจ้ง Claude — ชุดทดสอบจะหยุดเองถ้า web app ต้องล็อกอิน
4. ไฟล์ `config.test` › วาง URL ใน `testWebAppUrl: ''` › 💾 บันทึก (ไม่ต้อง deploy ใหม่)
5. รัน **`lfTest_1_ตรวจการแยกระบบ`** → แท็บ `ผลทดสอบ_APPS_SCRIPT` ทั้งสองแถวต้องเป็น "ผ่าน" — ถ้า "ไม่ผ่าน" **หยุด** แล้วแจ้ง Claude
6. รัน **`lfTest_2_ทดสอบทั้งหมด`** (2–5 นาที; ถ้าเวลาใกล้ 6 นาทีจะบันทึก "ข้าม" แล้วให้รัน `lfTest_3_รายงานรายเดือน` / `lfTest_5_ปิดบังหน้าสาธารณะ` แยกตามที่บันทึก)
7. รัน **`lfTest_6_ใส่คิวไม่ได้`** (≈ 1 นาที — เติมค่าชั่วคราวให้พื้นที่เต็มจริง แล้วลบเองทันที)
8. **ซ้อมย้อนกลับ** (≈ 5 นาที — ต้องวางโค้ดเอง 2 รอบ ในโปรเจกต์ทดสอบเท่านั้น):
   1. รัน **`lfTest_7_เตรียมซ้อมย้อนกลับ`**
   2. ไฟล์ `Code.gs` › ลบทั้งหมด › วาง `tests/fixtures/v2.0.0/lf_gas.gs` · ไฟล์ `MonthlyReport` › ลบทั้งหมด › วาง `tests/fixtures/v2.0.0/MonthlyReport.gs` › 💾 บันทึก
      (**ไม่ต้อง Deploy** — web app ทดสอบยังเป็นรุ่นใหม่ = สภาพเดียวกับขั้นย้อนกลับข้อ 1 ของระบบจริง)
   3. รัน **`lfTest_8_ตรวจหลังย้อนกลับ`** (รันบนโค้ด 2.0.0)
   4. วางโค้ดรุ่นใหม่กลับ: `Code.gs` ← `apps-script/lf_gas.gs`, `MonthlyReport` ← `apps-script/MonthlyReport.gs` › 💾 บันทึก
   5. รัน **`lfTest_8_ตรวจหลังย้อนกลับ`** อีกครั้ง
9. (ไม่บังคับ) **`lfTestOptional_EmailToMe`** — อีเมลทดสอบ 1 ฉบับถึงบัญชีที่กดรันเท่านั้น
10. แจ้ง Claude ว่า "รันแล้ว" — Claude อ่านผลจากแท็บ `ผลทดสอบ_APPS_SCRIPT`
11. หลัง Claude ยืนยันว่าเก็บผลครบ ปิดทุกอย่างตามลำดับ:
   1. รัน **`lfTest_9_เก็บกวาด`** (ลบ trigger และ Script Properties ของโปรเจกต์ทดสอบ)
   2. **Archive web app ทดสอบ**: ตรวจว่าชื่อโปรเจกต์มุมซ้ายบนคือ `TEST Lost&Found (ลบได้)` ›
      **การทำให้ใช้งานได้ › จัดการการทำให้ใช้งานได้** › เลือกรายการเว็บแอป (โปรเจกต์ทดสอบมีรายการเดียว) › **เก็บถาวร (Archive)**
      — **ห้ามทำขั้นนี้ในโปรเจกต์ระบบจริง** (ถ้าชื่อโปรเจกต์ไม่ใช่ `TEST…` ให้ปิดแท็บนั้น)
   3. รัน **`lfTest_10_ตรวจว่าปิดURLทดสอบแล้ว`** → ต้องเป็น "ผ่าน" (URL ทดสอบไม่ตอบข้อมูลแล้ว)
   4. แถวทดสอบในชีทและไฟล์ในโฟลเดอร์ `TEST_…` ใน Drive ลบเองได้ภายหลัง (ไม่มีข้อมูลจริง)

## สิ่งที่ทดสอบ และประเภทหลักฐาน

| กลุ่ม | กรณี | หลักฐาน |
| --- | --- | --- |
| แยกระบบ | ชีทไม่ใช่ชีทจริง, ชื่อขึ้นต้น TEST, config ทดสอบ, URL ไม่ใช่ของระบบจริง, ผู้รับอีเมลไม่มีคนอื่น, staff โดเมน .invalid, โฟลเดอร์ TEST_, เขตเวลาชีท = ระบบจริง (UTC+7) | จริง |
| ฟอร์ม → ชีท/รูป | ส่งไม่มีรูป, คิวไม่ค้างสถานะ "รอแถว", ข้อความไทยยาว (คิว ≤ 8,800 ไบต์), มีรูป (ไฟล์ลงโฟลเดอร์ TEST_ + URL ลงชีท), กดซ้ำ, ส่งพร้อมกัน 5 คำขอ, คำแนะนำฟอร์มนับได้ครั้งเดียวต่อการส่ง | จริง (HTTP เข้า web app ทดสอบ) |
| คิวแจ้งเตือน | LINE ส่งผ่าน HTTP จริง (ปลายทาง = web app ทดสอบ ไม่ใช่ LINE), ข้อความที่ส่งเข้า web app ทดสอบไม่สร้างแถวใหม่, อีเมลไม่มีผู้รับจนเลิกลอง, HTTP 404 → ไม่แน่ใจ, 200 ที่ไม่ใช่ success → ไม่แน่ใจ, DNS ผิด → ล้มเหลวแล้วลองใหม่สำเร็จ, เจ้าหน้าที่สั่งส่งใหม่, หมดเวลา → ไม่แน่ใจ, ค้าง "กำลังส่ง", หยุดส่งฉุกเฉิน `LF_QUEUE_PAUSE`, **หยุดระหว่างรอบ** (web app ทดสอบตั้งสวิตช์ตอนรับ LINE แรก → ส่งเฉพาะคำขอนั้น ที่เหลือไม่ถูกแตะ) | จริง ยกเว้น "หมดเวลา" = **mock** |
| รายงานรายเดือน | LINE ส่ง/อีเมลล้มเหลว, PDF ในโฟลเดอร์ TEST_, ค่าขึ้นต้น done, รันซ้ำไม่ส่ง LINE ซ้ำ, เจ้าหน้าที่ปิดช่องทาง, PDF หาย → สร้างใหม่จากตัวเลขชุดเดิม, ค้าง "กำลังส่ง", หยุดระหว่างรอบ (ส่ง LINE แล้วไม่ลองอีเมลต่อ) | จริง |
| รุ่น/ความเร็ว/ปิดบัง | health แยก version/build, build คำนวณได้จริง, web app = Head, ปิดบังเบอร์/รหัส/ชื่อ (เลขไทย คุณ อ. "ชื่อ" LINE ID อีเมลเลี่ยง @) บน runtime จริง, เวลาคำนวณ build, เวลาชุดข้อมูล | จริง |
| หน้าสาธารณะ (`lfTest_5_ปิดบังหน้าสาธารณะ`) | ชื่อในช่องชื่อของระเบียนอื่นถูกปิด, คำที่สั่งปิดใน `LF_PUBLIC_REDACT` มีผลทันที (ตั้งชั่วคราวแล้วลบ), ผลทั้งชุดไม่มีชื่อสังเคราะห์หลุด, เวลาปิดบัง 800 รายการสังเคราะห์ | จริง (HTTP) — ข้อมูลขนาด 800 รายการสร้างในหน่วยความจำ ไม่เขียนชีท |
| ใส่คิวไม่ได้ (`lfTest_6`) | พื้นที่ Script Properties เต็มจริง (นับไบต์) → ฟอร์มบันทึกแถว + บอกผู้ใช้ + `queue_failed`; มีที่ว่างแล้วใส่คิวใหม่และส่งครั้งเดียว; รอบถัดไปไม่ส่งซ้ำ | จริง (HTTP) |
| ซ้อมย้อนกลับ (`lfTest_7`, `lfTest_8` ×2) | Head = 2.0.0 + web app รุ่นใหม่: ไม่ส่ง LINE ของรายการ ไม่แน่ใจ/ปิดแล้ว/กำลังส่ง, รายการรอส่งและรายการที่รับระหว่างต่างรุ่นส่งครั้งเดียว, รายงานเดือนที่ส่งแล้วไม่ส่งซ้ำ; วางโค้ดใหม่กลับแล้วผลเดิม | จริง (โค้ด 2.0.0 ของ `main`) |
| ปิดหลังทดสอบ | trigger/ค่าที่ทดสอบสร้างถูกลบ, URL ทดสอบไม่ตอบหลัง Archive | จริง |

**สิ่งที่ชุดนี้ยืนยันไม่ได้**: กลุ่ม LINE จริงได้รับข้อความ (ทดสอบแบบควบคุมหลังเผยแพร่ ตาม `docs/release-plan.md` ข้อ 5)
และความเร็วกับข้อมูลจริง (~792 รายการ — ชีททดสอบมีไม่กี่แถว) · HTTP 5xx/429/redirect จาก web app ทดสอบทำไม่ได้ จึงทดสอบเฉพาะใน Node

หมายเหตุ: `release_test.gs` เก็บ "ลายนิ้วมือ" SHA-256 ของ ID ชีทและ deployment ระบบจริง (ย้อนกลับเป็น ID ไม่ได้)
