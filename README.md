# Lost & Found — งานจราจรและความปลอดภัย มหาวิทยาลัยมหิดล

หน้าเว็บ (GitHub Pages) + Google Apps Script ที่ผูกกับ Google Sheet "แจ้งของหาย"

```
ฟอร์ม TH/EN ──POST submit──▶ Apps Script (lf_gas.gs) ──▶ Sheet LF_New + รูปใน Drive (LostFound_Images)
Google Form เดิม ───────────▶ Sheet Form Responses ──trigger──▶ คิวแจ้งเตือน
                                     │
                         lfBuildRecords_()  ← ชุดข้อมูลกลาง (รวม 2 แหล่ง, เวลา ISO/UTC)
                                     │  แคช CacheService 180 วินาที + ล้างทันทีเมื่อมีการเขียน (force=1 อ่านใหม่)
      ┌──────────────────────────────┼───────────────────────────────┐
 getPublicData (สาธารณะ,      adminGetData (ต้องล็อกอิน)     รายงานรายเดือน (MonthlyReport.gs)
 ไม่มีชื่อ/เบอร์)               Dashboard / รายการ / PDF        ออกวันที่ 1 ของเดือนถัดไป
 index.html
คิวแจ้งเตือน (Script Properties lfq_*) ──trigger ทุก 1 นาที──▶ LINE (Cloud Function) + อีเมล, retry, log ในแท็บ LF_NotifyLog
```

## นิยามตัวเลข
- **รายการทั้งหมด** = LF_New (มีประเภท) + Form Responses (ปี ≥ 2020, จัดประเภทได้) ที่เวลาแจ้งไม่อยู่ในอนาคต
- **แบบฟอร์มรับของคืน** = รายการประเภท `รับของคืน` (หน้า index/รายการ)
- **สถานะรับของคืนแล้ว** = ทุกประเภทที่สถานะเป็น `รับของคืนแล้ว` (KPI Dashboard, PDF, รายงานเดือน)
- เดือน/วันคิดตามเวลาไทยจากเวลา "แจ้งเมื่อ" (Timestamp) ไม่ใช่วันที่เกิดเหตุ

## การเผยแพร่ (ลำดับ)
ดูแผนเต็มพร้อมเงื่อนไขหยุด/ย้อนกลับที่ `docs/release-plan.md` — สรุป:
0. **สำรอง (ไม่แก้อะไร)**: บันทึกหมายเลข deployment version ปัจจุบัน (Manage deployments), คัดลอกโค้ด Head ทั้งสองไฟล์เก็บไว้,
   ส่งออกรายการ Script properties (เฉพาะชื่อคีย์ + ค่า `LF_MONTHLY_REPORT_*`, `LF_NOTIFY_ENQUEUED`, `lfq_*`), File › Make a copy ของชีท (ใช้เทียบเท่านั้น)
1. Apps Script: วาง `lf_gas.gs` → ไฟล์ `lf_gas.gs.gs`, `MonthlyReport.gs` → `MonthlyReport.gs` (**ไม่แตะ** `config.private.gs`) แล้ว **Save**
   (trigger ทุกตัวใช้โค้ด Head ทันทีหลัง Save — ดูหัวข้อถัดไป)
2. Deploy › Manage deployments › แก้ไข deployment เดิม › New version (URL `/exec` ไม่เปลี่ยน)
3. Merge เข้า `main` → GitHub Pages อัปเดตหน้าเว็บ (ไฟล์สคริปต์มี `?v=2.1.1` เบราว์เซอร์จึงโหลดไฟล์ใหม่)
4. ตรวจหลังเผยแพร่: `?action=health` ต้องได้ `version: 2.1.1` และ `build` เดียวกับที่หน้า "ตรวจการแจ้งเตือน" แสดงเป็นโค้ด Head

### ช่วงที่แต่ละส่วนใช้คนละรุ่น
| ช่วง | trigger (คิว/รายงาน) | web app `/exec` | หน้าเว็บ | สิ่งที่เกิดขึ้น |
| --- | --- | --- | --- | --- |
| หลัง Save ก่อน Deploy | รุ่นใหม่ | รุ่นเดิม (2.0.0) | รุ่นเดิม | ตัวตามเก็บงานค้าง **หยุด** (ยังไม่มี build ของ web app) — คิวปกติยังส่งได้ |
| หลัง Deploy 10 นาทีแรก | รุ่นใหม่ | รุ่นใหม่ (คำขอเดิมที่ค้างอาจยังเป็นรุ่นเดิม) | รุ่นเดิม | ตัวตามเก็บงานค้างรอให้คำขอรุ่นเดิมจบ |
| หลัง Deploy > 10 นาที | รุ่นใหม่ | รุ่นใหม่ | รุ่นเดิม/ใหม่ | ทำงานครบ — หน้าเว็บรุ่นเดิมใช้ API ชุดเดียวกันได้ |
| หลัง Merge | รุ่นใหม่ | รุ่นใหม่ | รุ่นใหม่ (แคชเบราว์เซอร์ ≤ 10 นาที) | ครบ |

กลไก: `doGet`/`doPost` บันทึก **build** (ลายนิ้วมือของโค้ดทั้งโปรเจกต์) ของ web app ลง Script property `lf_webapp_version`
ตัวตามเก็บงานค้างทำงานเฉพาะเมื่อ build ของ web app = build ของโค้ด Head มาแล้วอย่างน้อย 10 นาที
ไม่มีค่า (รุ่น 2.0.0 เดิม) / build ไม่ตรง (แก้โค้ดแต่ยังไม่ Deploy แม้เลขรุ่นเดียวกัน) = หยุด — บันทึก `sweep_paused` / `sweep_resumed` เมื่อสถานะเปลี่ยนเท่านั้น
**ไม่ต้องรีบ Save แล้ว Deploy** — ความปลอดภัยไม่ขึ้นกับจังหวะเวลา

## รายการ "ไม่แน่ใจ" (สำหรับเจ้าหน้าที่)
- เกิดเมื่อระบบเริ่มส่งแล้วแต่ยืนยันผลไม่ได้ (execution หยุดกลางคัน, ปลายทางหมดเวลา, HTTP 504) — ระบบ **ไม่ส่งซ้ำเอง**
- ดูและจัดการที่หน้า **ตรวจการแจ้งเตือน** (`lostfound_notify.html`, ปุ่ม 🔔 ในหน้ารายการ พร้อมตัวเลขจำนวนที่ต้องตรวจ)
  เลือก: ยืนยันว่าได้รับแล้ว / ส่งใหม่ / ปิดโดยไม่ส่ง — ต้องใส่เหตุผล ระบบบันทึกชื่อผู้ใช้และเวลา (`LF_NotifyLog`: `staff_*`)
- ไม่มีวันหมดอายุเอง (เก็บได้สูงสุด 50 รายการ; เกินแล้วรายการเก่าสุดถูกนำออกพร้อมบันทึก `attention_overflow`)
- รายงานรายเดือนใช้หลักเดียวกัน แยก LINE / อีเมล และใช้ PDF + ตัวเลขชุดเดิมเมื่อสั่งส่งใหม่
- **ข้อจำกัด**: ระบบรับประกันไม่ได้ว่าข้อความถูกส่ง "ครั้งเดียวเสมอ" — กรณีไม่แน่ใจต้องให้คนตรวจ
  และถ้าเจ้าหน้าที่สั่งส่งใหม่ทั้งที่ปลายทางได้รับแล้ว ผู้รับจะได้ซ้ำ

## การย้อนกลับ
- หน้าเว็บ: `git revert <merge commit>` แล้ว push `main`
- Apps Script (วิธีหลัก): วางโค้ด 2 ไฟล์ที่สำรองไว้ในขั้น 0 กลับเป็น Head (**ไม่แตะ `config.private.gs`** — คงรหัสผู้ดูแลใหม่) › Save ›
  Deploy › Manage deployments › ✏️ deployment เดิม › Version: **New version** › Deploy (URL เดิม; trigger และ web app ได้โค้ดเดิมพร้อมกัน)
- วิธีฉุกเฉิน (เร็วกว่า): เลือก deployment version **ที่จดไว้ในขั้น 0 เท่านั้น** — web app จะใช้ config ของรุ่นนั้น
  (รหัสผู้ดูแลที่ใช้อยู่ก่อนเผยแพร่) ถ้าเปลี่ยนรหัสในขั้น 2ข ไว้ รหัสใหม่จะใช้ไม่ได้จนกว่าทำวิธีหลัก ·
  ห้ามเลือก version ที่เก่ากว่านั้น: รุ่นก่อน 19 ต.ค. 2569 อาจมีรหัสเดิมที่เคยอยู่ในประวัติสาธารณะ
- **ห้ามคืนชีทหรือ Script properties จากสำรองทั้งก้อน** รายการใหม่/คิว/สถานะรายงานที่เกิดระหว่างทางจะหายหรือถูกส่งซ้ำ
- ความเข้ากันได้เมื่อย้อนกลับเป็น 2.0.0 (ทดสอบด้วยโค้ดจริง 2.0.0 ใน `tests/fixtures`):

  - `lf_webapp_version`, `lf_sweep_gate` รุ่นเดิมไม่ใช้ ไม่ต้องลบ

## v2.1 (สรุปการเปลี่ยนแปลง)
- คิวแจ้งเตือน: ใส่คิวทันทีหลังบันทึกแถว (ภายใน lock) แล้วค่อยเติม URL รูป; ถ้ารูปไม่มาภายใน 10 นาทีจะส่งโดยไม่มีรูป
  และทุก ~15 นาที trigger คิวเดิมจะตามเก็บแถวใน LF_New ที่ไม่เคยเข้าคิว (ย้อนหลังไม่เกิน 6 ชม. และเฉพาะหลังเริ่มใช้ v2.1)
  ใช้ Script Property `LF_NOTIFY_ENQUEUED` (ลบได้ — ระบบจะเริ่มนับใหม่โดยไม่แจ้งรายการเก่า)
- payload LINE เพิ่ม `timestampUtc` (ISO UTC) และ `timestampBangkok` (+07:00); `timestamp` เดิมคงรูปแบบเดิม
- รายงานรายเดือน: `LF_MONTHLY_REPORT_yyyy-MM` เป็น JSON แยกสถานะ LINE / Email; LINE ที่ไม่มี URL หรือ HTTP ไม่ใช่ 2xx = ล้มเหลว
  วันที่ 2–3 จะลองเฉพาะช่องทางที่ยังไม่สำเร็จด้วย PDF เดิม; ค่าข้อความเดิม `done …` ยังถือว่าส่งแล้ว
- session ผู้ดูแลผูกกับ salt/hash ของบัญชี: เปลี่ยนรหัสใน `config.private.gs` แล้ว session เดิมใช้ไม่ได้ทันที
  (หลังเผยแพร่ v2.1 ครั้งแรก ผู้ดูแลที่ล็อกอินค้างไว้ต้องล็อกอินใหม่ 1 ครั้ง)
- API สาธารณะซ่อนเลขบัตร 13 หลัก/ตัวเลขยาว ≥ 9 หลัก และย่อชื่อหลังคำนำหน้า (นาย/นาง/นางสาว/น.ส./Mr./Ms. …);
  autofill สาธารณะไม่ส่งค่า pending ที่มีตัวเลขยาว อีเมล คำนำหน้าชื่อ หรือยาวเกิน 80 ตัว
- หน้า index: เปิดซ้ำจะแสดงข้อมูลสาธารณะที่โหลดไว้ (localStorage `lf_pub_v1`, ไม่เกิน 24 ชม.) ทันทีพร้อมป้ายเวลา แล้วโหลดใหม่เสมอ
  — ไม่เก็บข้อมูลผู้ดูแลในเครื่อง

## ความปลอดภัย
- รหัสผ่านผู้ดูแลตรวจที่เซิร์ฟเวอร์ (salt + SHA-256 วนซ้ำ) ล็อก 15 นาทีเมื่อผิด 5 ครั้ง, session 6 ชั่วโมงใน CacheService
- token ถูกส่งใน body ของ POST ทุกคำสั่งผู้ดูแล — หน้าเว็บไม่ได้ตัดสินสิทธิ์เอง
- รหัสผ่านเดิมเคยอยู่ในไฟล์สาธารณะและยังอยู่ในประวัติ git จึงต้องใช้รหัสใหม่เท่านั้น
- API สาธารณะไม่ส่งชื่อ เบอร์โทร หน่วยงาน ผู้บันทึก และไม่ส่งรูปของเคส "รับของคืน" (มักเป็นบัตรประจำตัว)
  เบอร์โทร/อีเมลที่ผู้แจ้งพิมพ์ไว้ในรายละเอียดถูกปิดบังเป็น `[ซ่อนเบอร์]` / `[ซ่อนอีเมล]`

## ขอบเขตการปิดบังข้อมูล

การปิดบังทำสามชั้น เรียงจากที่เชื่อถือได้มากไปน้อย

1. **ตัดทั้งฟิลด์** — `lfPublicRecord_` ไม่ส่ง `name` `phone` `dept` `personType` ออกจาก API เลย
   ชั้นนี้ไม่ใช่การเดา จึงเป็นด่านหลัก
2. **ปิดบังตามคำนำหน้า** (`lfMaskNames_`) — สำหรับชื่อ *บุคคลที่สาม* ที่ผู้แจ้งพิมพ์ไว้ในรายละเอียด
   เช่น ชื่อบนบัตรที่เก็บได้ มีบัญชียกเว้นคำประสม (`LF_TITLE_EXCEPT`) กันคำอย่าง
   "นายกสภา" "นายจ้าง" "นางเลิ้ง" ไม่ให้ถูกย่อจนอ่านไม่รู้เรื่อง
3. **ปิดบังชื่อในระเบียน** (`lfRedactKnownName_`) — เอาชื่อของเจ้าของระเบียนนั้นเองมาตัดแบบตรงตัว
   จับได้แม้ไม่มีคำนำหน้า เช่น "บัตรนักศึกษาชื่อบอใบไม้ ตอเต่า" (ชื่อสมมติ)

### สิ่งที่วิธีนี้ยังจับไม่ได้

- **ชื่อบุคคลที่สามที่ไม่มีคำนำหน้า** เช่น "กระเป๋าของสมชาย" — ชั้นที่ 2 ไม่เห็นเพราะไม่มีคำนำหน้า
  และชั้นที่ 3 ไม่เห็นเพราะไม่ใช่ชื่อในระเบียน **นี่คือช่องโหว่ที่เหลืออยู่จริง**
- **ชื่อที่สั้นกว่า 4 ตัวอักษร** ไม่ถูกนำไปตัดในชั้นที่ 3 เพราะเสี่ยงชนคำทั่วไป (เช่น ชื่อเล่น "ขนม")
- **คำนำหน้าที่เขียนติดกับอักษรไทยตัวหน้า** เช่น "ติดต่อนายสมชาย" — ตั้งใจไม่จับ
  เพื่อไม่ให้คำอย่าง "ทำนาย" "ขุนนาง" ถูกตีความผิด
- **คำประสมที่ยังไม่อยู่ในบัญชียกเว้น** จะถูกย่อผิด แก้ได้โดยเติมคำลงใน `LF_TITLE_EXCEPT`
- **นามสกุลที่พ้องกับคำทั่วไป** อาจถูกคงไว้ ถ้าขึ้นต้นด้วยคำใน `LF_NOT_SURNAME`
- ภาษาไทยไม่เว้นวรรคระหว่างคำ การตัดคำด้วย regex จึงไม่มีทางถูกต้อง 100%
  **ชั้นที่ 2 และ 3 เป็นด่านรอง ไม่ใช่หลักประกัน** หลักประกันคือชั้นที่ 1

ชุดทดสอบอยู่ใน `tests/gas.test.cjs` หัวข้อที่ขึ้นต้นด้วย `PII:` ใช้ข้อมูลสังเคราะห์ทั้งหมด
